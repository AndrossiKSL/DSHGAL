# 更新素材、代码与桌面 EXE

当前桌面版把前端、代码和美术一起封在 EXE 里，没有外置素材热更新或自动更新器。因此新美术或代码要进入接收方的桌面版，需要重新构建并封包；修改 GitHub README 不会改变已经下载的 EXE。

| 修改内容 | 源码 / 网页版 | 单文件桌面版 |
| --- | --- | --- |
| 角色立绘、头像、场景、UI 或字体 | 按素材同步说明更新清单与哈希，构建并重启服务 | 重新制作 EXE |
| 引擎、前端或后端适配 | 构建、检查并重启；DSH 插件通过官方管理命令更新 | 重新制作 EXE；DSH 宿主侧修改另行更新插件 |
| README、截图、普通说明文档 | 更新仓库即可 | 不影响游戏，无需仅为 README 重打 EXE |
| 随包分发的许可或法律声明 | 更新对应发布物的声明 | 下一次分发的 EXE 应带更新后的声明 |
| 个人配置、存档、模型与凭据 | 保存在本机 | 不进入 EXE，也不上传 GitHub |

先按 [ASSET-SYNC.md](ASSET-SYNC.md) 显式导入已验收素材，再执行：

```sh
npm run verify
npm run package:desktop
npm run package:share
```

制作新的公开版本前同时更新 package.json、package-lock.json 与 apps/desktop/package.json 的版本号。关闭需要替换的旧 EXE 后再更换它，保留旁边的 DSHGAL-data 目录。DSH 后端存档继续保存在 DSH 的数据目录中。

新增素材应保留现有角色和动作 ID，更新资源清单和 SHA256；不要仅覆盖一张图片就忽略映射或许可。正在生产的新图不会被应用自动扫描或上传。存档结构变更仍需另做迁移与回归验证，不能仅凭保留目录承诺所有版本兼容。
