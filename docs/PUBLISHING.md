# 脱敏公开发布

公开源码来自 `scripts/release-files.mjs` 的文件白名单，不直接推送个人工作仓库的完整历史。保留上游作者、版权文本、来源链接和许可边界；公开提交使用 GitHub noreply 邮箱。

发布前执行 `npm run verify`，核验所有运行美术的 SHA256，并检查待发布的文件名、文本与图片元数据。排除个人配置、API key、凭据、存档、游戏对话、Agent 任务记录、浏览器数据、原始生图目录、旧试验记录、依赖缓存和本机 Git 历史。

GitHub 用户名、仓库地址和 noreply 邮箱也属于公开身份，不能把其中类似手机号的标识自动当作已脱敏。检查文件正文之外，还应核验所有公开提交的作者 / 提交者字段，以及实际 EXE、ZIP 和 Release 说明；GitHub 自动生成的邮箱不等于匿名邮箱。

更换公开身份时，含旧信息的提交和附件继续留在私有归档中。新的公开仓库使用独立、干净的提交历史，确认没有旧 Git 对象、标签或附件后再开放。此前已被他人保存的副本不在本仓库控制范围内。

旧版生图桥的本机绝对 SSH 配置路径已移除。需要云端生图时，由接收方通过 XG_CONFIG 环境变量、显式 sshConfigPath 或自己的 DSH 数据目录配置；公开包不会自动查找维护者的私人磁盘位置。脱敏检查同时处理源码与 JSON 中转义后的路径。

EXE 和完整 ZIP 作为 GitHub Release 附件分发，不提交到源码 Git。README 的 22 位角色头像、界面图、图标和背景来自当前冻结素材；展示这些图片不改变原许可。

本项目程序主体沿用上游 MIT；配套工坊保留原有 UNLICENSED 元数据。美术、字体和不同上游组件各自适用对应条件，不能将整个仓库统称为纯 MIT 素材包。完整来源见 [CREDITS.md](../CREDITS.md)、[NOTICE.md](../NOTICE.md) 与 [依赖清单](../third_party/DEPENDENCIES.md)。

更新源码时使用受控的公开分支或副本，保持发布历史连续；不要将本机历史意外合并到公开分支，也不要强推覆盖别人已经提交的工作。所有上传都应再次确认目标仓库及 Git diff。
