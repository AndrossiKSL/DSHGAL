# 2.2.1 布局迁移与分享验收

本版本把原独立前端整理为 DSHGAL 开发根目录，主分支为 main。原 GAL 历史和角色工坊历史已经保留，配套工坊源码置于 integrations/dsh-character-party。后续二次开发以本目录为准。

## 目录与部署

- 独立服务移到 apps/standalone，构建产物统一为 dist。
- 源码、运行美术、部署工具、集成与本机数据分别放到 src、assets、deploy、integrations 和 .local。
- 完整 ZIP 携带当前美术、UI、预构建文件、Agent 指南与 SHA256 文件清单。
- DSH 部署从现有产物生成插件包并内附配套工坊，不依赖旧电脑上的源码路径，也不要求接收方重新构建。
- Hermes 部署检查 ACP，并复用接收方自己的推理接口、模型与登录。
- 凭据、用户存档、日志、Git 目录、历史试验物料和 node_modules 不随分享包分发。

## 已完成验证

- 主项目 113/113 测试、角色工坊 42/42 测试通过，构建和分享审计通过。
- 实际分享 ZIP 在空白目录解压后，无 node_modules 启动成功；标题、脚本、头像和字体路由返回 200。
- 分享包逐文件 SHA256 校验和 DSH 部署 dry-run 通过。
- 实际插件 tgz 经 pnpm 11.21.0 在临时项目离线安装通过；安装后的内附角色工坊可由 Node 正常加载。
- 实际 Hermes 安装通过部署脚本 ACP 握手，并在临时副本写入接收方本机配置。没有调用收费模型生成剧情或执行真实文件任务。
- 本机独立前端已从新目录启动。现有 DSH 主服务与正式存档未迁移、覆盖或强制重启。

## 资产与旧物料

美术保持原 2.2 快照，本次没有导入新的生产结果。后续按 ASSET-SYNC.md 更新。素材和配套工坊原有许可声明保留，没有统一改标 MIT。

旧工作副本先归档，再清除冗余代码；必要的旧路径只作兼容入口。具体本机清理结果保存在 .local/migration-cleanup.json，历史归档不放入分享包。资产生产工程与生图目录不在清理范围。
