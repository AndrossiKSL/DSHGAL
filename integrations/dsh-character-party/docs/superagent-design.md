## 0.2 已实现

角色持久身份、项目共享记忆、DSH 原生子会话、任务依赖、读写互斥、取消、重启中断标记和准确的交付状态沿用 0.1。

新增多套模型配置、统一模型与角色例外、按任务类型细分、任意手选模型、目录刷新、API 凭据引用、连接测试及原生流式工具适配。用户确认的省量策略优先：日常可所有角色用同一个模型，工程才切换分工。角色家族只是自动匹配建议，不限制用户跨家族选择。任务保存提交时的配置快照，切换不会更换运行中的模型。

Kimi 首选 K3.1 Pro、Grok 首选 4.7、混元首选 HY4、Qwen 首选 3.8 Max。公开目录能直接匹配 12 个角色家族；其余跟随统一模型或手选。全部型号未做性能对比，岗位标签是初始建议。

GAL 1.2 主剧情读取同一配置。同模型只请求一次导演；不同模型的在场角色分别改写自己的台词和动作，导演保留规范场景、选择与关系规则。提供给单角色的上下文遵守角色可知范围。失败不推进世界。

已进行四个指定型号的少量真实连接测试，以及 K3.1 Pro 的原生 DSH 只读工具和 structured_output 往返。没有据此宣称全部 30 个型号均可用于所有任务。

## 0.3 从原型吸收并实现的结构

1. 长期总控维护目标、项目、约定和任务索引，耗时工作交给角色 Worker；GAL 日常交流不等待后台编码。
2. 工作项具有稳定 ID，补充输入直通原工作项，避免反复创建会话丢失过程。
3. 输入、成果和事件有明确来源，先持久化再交付；断线恢复先核验已有产物，不盲目重放写入。
4. 分层召回共享事实、角色个人记忆及工具细节，总控读取摘要和引用；私人剧情记忆继续遵守 heardBy。
5. 成果以角色语气简短回流 GAL，保留原生工具轨迹和可打开产物；关系数值不改变权限。
6. 心跳、超时与进展优先用确定性监督，需要理解时才额外调用模型。

上述长期 Router、持续角色会话、消息追加和成果回信已实现。回信保留线程、模型、会话与文件来源，玩家主动继续剧情时才引用，不自动推进剧情。ST 角色卡导入等待用户提供格式。

## GO 与凭据边界

使用 `https://opencode.ai/inference/go/openai/v1/chat/completions` 和官方 `/inference/go/v1/models`。每个原生子会话复用自己的稳定 `x-opencode-session`，并使用项目自身 User-Agent。凭据只存 DSH credentials，公开状态只返回已配置标记。

自定义兼容接口目前实现文本和工具调用，多模态请用 DSH 原生提供器。服务端套餐范围、余额兜底由账号规则决定；插件不自行转用按量入口。V1 与 Agent-preview 保持原样作为回退包。

## 持续会话与后端

`SuperAgent` 将线程、输入事件、工作会话索引、交付和审批写入原 party 状态的 super 扩展，不破坏旧格式。计划执行完不等于目标完成：写入之后必须有其他角色的独立审查，全部成功后才生成本轮总结与 GAL 回信。依赖失败会收敛为等待处理，不生成成功交付。

原生 DSH 使用 startContinuable / prompt，冷恢复保留 child ID 和工作区父会话。WorkBuddy 使用官方 CLI ACP，保留 session ID 并 session/load。冷恢复失败不会静默开启新会话。每次重试使用新的 execution ID，防止误取上次输出。项目、角色、岗位和模型共同决定会话键。

Router 对已知线程输入直接排入原线程，不再次调用统筹拆分；补充输入在依赖完成后续接工作角色。角色个人剧情仍由 GAL 管理，工具任务只获得该任务需要的剧情摘要与项目工作上下文。主剧情可使用 WorkBuddy 文本后端，关闭工具与项目文件。

`/character-party-api` 支持 workspace-open、thread-open/input/pause/resume/cancel/recall、notice-ack、approval-resolve。`/character-party-artifact` 只下载登记过且 SHA256 未改变的项目内文件，使用窗口令牌。并发上限、项目写互斥、读审查守卫、无工具统筹、超时和单轮调用上限均在宿主层控制。

## 实施边界

本版服务于同一台电脑的 DSH 与 GAL 独立入口，没有引入云端常驻、跨设备同步、外部消息推送或自动 GitHub 发布。模型输出和角色总结是带来源的自述；实际构建与浏览器验收单独记录。关系数值、剧情发展和模型岗位都不授予额外工具权限。
