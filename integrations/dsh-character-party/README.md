# DSH 角色 Agent 工坊 0.3.0

GAL 是交互界面，DSH 是执行底座。22 位角色共用当前项目的事实、委托和成果记录；每个工作线程保存可续接的角色子会话，加载角色身份、选定模型和共享记忆。只调用参与本次任务或场景的角色，不会每轮唤醒全部 22 位。

## 使用

从 GAL 阅读页打开「工坊委托 → 模型分工」。也可直接访问 DSH 的 `/character-party/`。

1. 在「API 来源」配置 GO Plan 或 OpenAI 兼容接口，保存后获取模型列表。已有 DSH 提供器会自动列出。修改 Key 时留空会保留原凭据；连接测试会发起一次简短模型请求。
2. 在「使用配置」选择日常、工程或复制一套自定义配置。设置统一模型后，未单独指定的角色都跟随它；也可以让少数角色例外。未指定统一模型时沿用 DSH 当前模型。
3. 点「按角色匹配」填入可用的同族候选，再手动调整。匹配是建议，所有角色均可选择其他模型。Kimi 优先 K3.1 Pro，Grok 优先 4.7，混元优先 HY4，Qwen 优先 3.8 Max；目录没有的型号不会虚构。
4. 「仅保存」保留配置而不切换当前模式；「保存并启用」立即用于后续任务和剧情。主页面也可快速切换。刷新列表失败会保留上次目录、角色绑定和未保存选择。

默认的「日常省量」采用并发 1、每次请求最多输出 1600 tokens、注入记忆最多 12000 字符、低思考档。「工程分工」采用并发 3、输出 8000、记忆 40000、高思考档。这些值均可调整；模型不支持的思考档会适配为其支持的档位。最多保存 12 套配置、12 个自定义 API。

展开「用量与任务类型设置」可为统筹、界面、编码、审查、调研、角色交流设置公共模型或某角色的任务专属模型。优先级为角色的任务专属模型、角色默认模型、公共任务模型、统一模型、DSH 主会话模型。进行中的任务及其团队子任务保留提交时的配置快照。

输出上限针对每次模型请求，并非整项工作的总 token 或费用上限；原生工具执行可能需要多轮请求。完成记录展示提供器回传的输入、输出和缓存 token。插件不会自动启用按量入口，服务端订阅与余额规则仍由 API 账号控制。

## GAL 与真实工作

工坊支持单人委托、多人协作和无工具的角色交流。多人模式由统筹拆成最多 8 个任务，按依赖执行并展示角色成果、实际模型、用量与原生会话来源。执行继承父会话工作区、预设、沙箱与审批；调研/审查只开放读与检索工具，角色交流不提供工具，子任务不会递归拉起队伍。读任务可以并发，写任务与本队列内同项目其他任务互斥；外部编辑器不在队列锁内。

GAL 1.2 起，主剧情也读取当前配置：在场角色使用同一模型时只生成一次场景；某位角色单独选了不同模型时，仅由它的模型改写该角色台词、表情和动作。场景事实、说话者、关系规则和选项仍由导演校验，不会把其他角色私密记忆交给它。模型失败会保留当前剧情并允许重试。

身份、项目记忆和工作线程持久化。共享记忆按项目目录隔离，区分玩家事实与 Agent 自述；自述不等于验证事实。ST 卡导入仍未实现。

## 接口与存储

服务入口为 `/character-party-api`。GAL 以可选依赖加载本插件。工作记录、配置和共享记忆在 DSH `storages/dsh-character-party/party.json`；自定义 API 元数据在同目录 `api-sources.json`。Key 仅通过 DSH 原生 credentials 服务保存，前端只获取是否已配置，不写入仓库、世界存档、角色卡或浏览器存储。GO 接入使用官方接口、项目自身 User-Agent，以及按子会话稳定的 `x-opencode-session`。

自定义 OpenAI 兼容接入当前支持文本、流式结果和工具调用。图片/附件需选用 DSH 原生多模态提供器。ComfyUI、Image2 仍需各自的图像服务或工作流，选择文本模型不会替代图像生成引擎。

安装到 GAL 所在 DSH profile 的 `node_modules`，使用 GAL 项目的 `scripts/deploy-local.ps1` 同步完整源文件和构建产物。部署保留本机插件配置、凭据和存档。API 配置、刷新和模型切换无需重启 DSH。

```powershell
npm run check
npm test
```

## 长期委托与 Router

「长期委托」可以打开任意已存在的本地项目，指定角色、单人或团队、任务类型及模型配置。总控保存计划与依赖，角色处理真实文件，独立审查完成后才汇总交付。写任务按项目互斥，独立读任务可并行。已知工作线程的新输入直接进入原线程，运行中追加的要求排入依赖队列，保留原角色会话；它不重开一个没有历史的一次性 Agent。

每项委托固定提交时的模型配置。默认日常配置保持省量，工程配置仅在用户选择后启用。原生 Router 会话按项目、统筹角色和模型复用，具体工作角色按线程、岗位和模型保存会话。不会预先运行 22 个角色。每轮最多 24 次工作调用，单次原生请求沿用 token 设置；整体用量展示后端实际回传值，并非硬性费用预算。

暂停会停止运行中的轮次；取消会终止本轮待办。DSH 重启后把未完成线程停在「中断」，用户点恢复时续接原会话，先核对文件，只重新排入未完成任务。已完成写入不自动重放。单轮超过 20 分钟会中断并保留记录。

交付文件记录路径、SHA256 和来源工作项，下载时重新校验文件未变化，拒绝工作区外文件、配置与凭据。工作记录可召回原线程、角色会话和事件。GAL 的工坊回信只回到关联世界；玩家继续剧情时角色才引用工作成果，后台任务不会推进剧情或改变关系。

## WorkBuddy 执行后端

模型目录新增「WorkBuddy」来源，使用本机官方内置 CLI 的 ACP 接口，沿用桌面登录。支持 Auto 或目录提供的指定型号，可与 GO/DSH 模型在同一个工程配置中混用。真实工作使用可续接的 ACP 会话；普通剧情使用无工具的文本请求。列表获取不执行推理，连接自检不加载用户文件或项目设置。

只读工作禁止文件写入；写工作只在选定项目内进行。未知命令等权限请求显示在原委托中，由用户单次决定；取消任务会取消等待。不会使用 skip-permissions、导出桌面凭据或接入用户 MCP。显示 WorkBuddy 回传的 token 与积分；输出上限由其平台规则控制，工坊的单次 token 参数不作为 WorkBuddy 硬上限。日常/工程另有限制工具轮次。

本机已实测 DSH K3.1 Pro 及 WorkBuddy Auto 的文件读取、第二轮原会话续接；GO K3.1 Pro、Grok 4.7、HY4、Qwen3.8 Max 的独立连接通过。WorkBuddy K3.1 Pro、HY4 的固定提示测试通过。其他目录项不标记为已连通；原生 Codex GPT-6 Sol 的先前探针仍为 fetch failed。模型岗位可自由调整，没有进行全型号能力排名。

## 验证与封存

`npm run check` 检查服务和浏览器脚本；`npm test` 覆盖模型配置、来源安全、队列、持续线程、失败依赖、暂停恢复、原会话续接、单次权限和文件边界。CLI 测试夹具不调用收费模型；实际模型任务与构建记录见 GAL 的发布验收文件。

V1、V2 基线与本次超级 Agent 版本分别封存，部署保留本机配置、Key 和游戏存档。Windows 原生命令需满足 DSH 官方的目录权限要求；插件不绕过宿主沙箱。接入细节见 [本机 Agent 路由](docs/local-agent-routing.md) 和 [持续工作设计](docs/superagent-design.md)。

本轮最终验收为 41 项工坊测试、43 项 GAL 测试与实际 9988 浏览器通过。真实 DeepSeek/Kimi/Grok 团队完成独立页面实现、复核和总结；WorkBuddy Auto 通过现有 Bash 执行及文件回读。DSH 原生 PowerShell 与通过 WorkBuddy Bash 调用 PowerShell 在本机仍不可用，未扩大工具集合或修改真实项目权限。详见 GAL 项目的 docs/validation-superagent.md。
